# 第 3 关 · 结图者

kNN 图 + 边特征。

**一句话：第 1、2 关把每个核苷酸当成孤立样本，第 3 关第一次让它们互相知道对方的存在。**

# 一、特征处理：从「看自己」到「看关系」

## 大白话版

把这个任务想成：给你一条 RNA 的晶体结构，**把四种碱基全部挖掉**，
只留下磷酸骨架、糖环，以及糖苷氮——也就是只告诉你「碱基从这个位置长出来、
朝这个方向」，但不告诉你长的是什么。问每个位置原来是 A、C、G 还是 U。

**第 1、2 关的做法：只看单个核苷酸自己。** 周围挤不挤、配不配对、
骨架拧成什么姿势（eta/theta）、碱基相对糖环转了多少度（chi）。

**为什么走不远**：A 型螺旋的几何是碱基无关的。茎区里一个 G 和一个 U，
骨架姿势几乎一模一样。你自己拿一个孤立核苷酸的骨架来看，也猜不出它是什么碱基。
第 2 关实测对上了——只用 eta/theta 只有 **37.6%**，比瞎猜（34.9%）才高 2.7 个百分点。
eta-theta 图上那一团就是这件事的图形版（见自测第 3 题）。

**你自己是怎么猜碱基的？** 不是看这个核苷酸自己，是看它跟谁发生关系：
对面配的是谁（对家是 G，这边几乎一定是 C）、在茎里还是在环里、
在什么 motif 里（GNRA 四环、U-turn、kink-turn）。**全是关系，不是属性。**

第 3 关干的事就是：把「关系」取出来喂给模型。

## 专业术语版

把每条链从**一组独立样本**变成一张**几何图（geometric graph）**：

- **节点** = 核苷酸，节点特征 V 还是第 2 关那 10 维，一个字没改
- **边** = kNN 图，以 C4' 为中心原子取 k=16 个最近邻（空间近邻，不是序列近邻）
- **边特征 E** = 两个核苷酸之间 4×4 个原子对的距离，各用 16 个高斯基函数（RBF）展开，
  再拼上 33 维的相对序列位置 one-hot

```
E 的维度 289 = 4×4 对原子 × 16 个 RBF + (2×16+1) 相对位置
                     256                 +        33
```

张量形状（一条 100 nt 的链，k=16）：

| 张量 | 形状 | 几个数 |
|---|---|---|
| V 点特征 | [100, 10] | 1,000 |
| idx 邻居表 | [100, 16] | 1,600 |
| **E 边特征** | **[100, 16, 289]** | **462,400** |
| 其中 relpos | [100, 16, 33] | 52,800 |

**第 2 关一条链只看到 1,000 个数，第 3 关看到四十多万个。**

## 和第 2 关到底差在哪

| | 第 2 关 | 第 3 关 |
|---|---|---|
| 一个样本是什么 | 一个核苷酸 | 一条链（图） |
| 输入 | 10 个数 | V[L,10] + idx[L,k] + E[L,k,289] |
| 知不知道谁挨着谁 | **不知道**，摊平后链的边界都没了 | 知道 |
| 知不知道两个核苷酸的相对姿态 | 不知道 | **知道**（16 个原子对距离） |
| 知不知道邻居在序列上多远 | 不知道 | **知道**（33 维 one-hot） |
| 配对信息 | 有（点特征第 9 列，手喂的） | **一样是那一列，没加新的** |
| 模型 | MLP | MeanPoolGraph（见下，只做了一半） |

**常见误会：第 3 关没有新增配对信息。** 配对那一维第 2 关就有了，这一关一个字没动。
第 3 关新加的是**下面三样**，而配对是网络将来有可能**自己发现**的东西，不是新喂的。

### 新增一 · 邻居表：谁在谁身边

以 C4' 为锚，在三维空间里找最近的 16 个核苷酸。

在茎区，这 16 个里会自动包含：沿骨架上下堆叠的 i±1、i±2，
**对面链上配对的那个 j，以及 j 的上下邻居 j±1**。

也就是说——**配对伙伴本来就在邻居表里**，只是模型还不知道哪一个是。

### 新增二 · 16 个原子对距离：接触指纹（最重要，最容易被漏掉）

一个核苷酸的 P、C4'、C1'、N 四个原子构成一个小刚体，像一个有方向的箭头：
磷酸在尾巴，糖苷氮指向碱基。

我们给的不是一个距离，是**两个小刚体之间 4×4 = 16 个原子对的距离**。

**为什么要 16 个而不是 1 个：一个距离只能说「多远」，16 个距离能说「以什么姿态相对着」。**
两个核苷酸挨得一样近，但一个是头对头、一个是并排，这 16 个数完全不同。
用术语说，这组距离把两个局部坐标系的**相对位置和相对转角**都锁住了（差一个镜像）。

三种接触各有特征性的数字：

| 关系 | C1'-C1' | 两个磷酸 | 两个糖苷氮 |
|---|---|---|---|
| **WC 配对** | ≈ 10.4 Å，几乎是常数 | 隔得远，横跨螺旋 | 大致面对面 |
| **沿骨架堆叠（i, i+1）** | 明显更近，6 Å 上下 | 沿骨架只差一步 | 几乎平行朝同一边 |
| **空间上凑巧挨着** | 什么值都有，散 | 散 | 散 |

**配对有一组刻板的数字，堆叠有另一组，凑巧挨着没规律。**
这 16 个数就是「这两个核苷酸是什么关系」的指纹。

#### 用自己的数据量一遍（待跑）

重点看**标准差**：配对那行应该很小（刻板），凑巧挨着那行应该很大（随机）。
标准差小 = 这个数字是可靠的指纹，网络能靠它认出关系。

| 关系 | n | C1'-C1' | P-P | N-N | C4'-C4' |
|---|---|---|---|---|---|
| 配对（WC 对家） | | | | | |
| 堆叠（i, i+1） | | | | | |
| 凑巧挨着 | | | | | |

```python
import numpy as np, sys; sys.path.insert(0, ".")
from minif import data
tr = data.load("rna", "train")
P, C4, C1, N = 0, 1, 2, 3                    # coords [L,4,3] 的原子顺序

pair, stack, rand = [], [], []
rng = np.random.default_rng(0)
for r in tr:
    c, pt = r["coords"], np.asarray(r["partner"]); L = len(pt)
    for i in range(L):
        if pt[i] > i:
            pair.append((c[i], c[pt[i]]))                      # WC 对家
    for i in range(L - 1):
        stack.append((c[i], c[i+1]))                           # 沿骨架堆叠
    for _ in range(min(L, 60)):
        i, j = rng.integers(0, L, 2)
        if abs(i - j) > 3 and pt[i] != j and np.linalg.norm(c[i, C4] - c[j, C4]) < 16:
            rand.append((c[i], c[j]))                          # 空间凑巧挨着

def stats(ps, name):
    a = np.array([p[0] for p in ps]); b = np.array([p[1] for p in ps])
    d = lambda x, y: np.linalg.norm(a[:, x] - b[:, y], axis=-1)
    print("%-16s n=%6d   C1'-C1' %5.1f±%4.1f   P-P %5.1f±%4.1f   N-N %5.1f±%4.1f   C4'-C4' %5.1f±%4.1f"
          % (name, len(ps), d(C1,C1).mean(), d(C1,C1).std(), d(P,P).mean(), d(P,P).std(),
             d(N,N).mean(), d(N,N).std(), d(C4,C4).mean(), d(C4,C4).std()))

stats(pair, "配对(WC对家)"); stats(stack, "堆叠(i,i+1)"); stats(rand, "凑巧挨着")
```

### 新增三 · 相对序列位置：这个邻居是从哪来的

残基 30 在茎区，和 75 配对。它的空间近邻是 29、31、75、76。代码走一遍：

```python
off = resnum[idx] - resnum[:, None]      # 邻居 j 在序列上离 i 多少位
off = np.clip(off, -16, 16) + 16         # 截断到 ±16，平移成 0~32 的下标
oh[...] = 1  在第 off 格                  # 33 格里只有一格是 1
```

```
邻居 29   序列偏移  -1   clip后  -1   one-hot 第 15 格 = 1
邻居 31   序列偏移  +1   clip后  +1   one-hot 第 17 格 = 1
邻居 75   序列偏移 +45   clip后 +16   one-hot 第 32 格 = 1
邻居 76   序列偏移 +46   clip后 +16   one-hot 第 32 格 = 1   <- 和 75 同一格
```

33 = 2×16+1，就是 −16 … 0 … +16 这 33 种可能，两端是饱和桶（「≥16 位以外」）。

**生物意义**：偏移 ±1 是沿骨架走过来的堆叠邻居；偏移被截断到 ±16 的，
是从老远折回来的——在 RNA 里那基本就是二级结构的对家或者三级接触。
**这两种邻居对猜碱基的价值完全不同**：对家几乎直接给出答案，骨架邻居基本不给。
模型没有这个常识，得明着喂。

## 为什么要 one-hot：同一个套路的第三次出现

**序列偏移是分类，不是刻度。** +1 是堆叠邻居，+2 可能隔着一个 bulge，+45 是配对对家。
直接喂一个整数进线性层，等于强迫模型假设「偏移越大影响越单调变化」——
那就是说 +45 的影响是 +1 的 45 倍，荒谬。one-hot 让每一类自己学自己的权重。

这是同一句话的第三次出现：

| 量 | 原始形式的问题 | 怎么处理 | 维度 |
|---|---|---|---|
| 二面角（第 2 关） | −179° 和 179° 挨着，数值差 358 | 拆 sin/cos | 1 → 2 |
| 原子间距（第 3 关） | 一个标量线性进网络表达力太弱 | 摊成 16 个高斯基（RBF） | 1 → 16 |
| 序列偏移（第 3 关） | 是分类不是刻度 | one-hot | 1 → 33 |

**宁可维度冗余，也不要把一个有结构的量压成一个标量。**

one-hot 用 33 维装 log2(33) ≈ 5 比特，信息上确实「浪费」。
但目的不是压缩，是**给第一层 Linear 33 个独立的权重列**。

## 这一关只做了一半

模型是 `MeanPoolGraph`：

```python
def forward(self, V, E, idx):
    return self.head(torch.cat([V, self.embed_E(E).mean(dim=1)], dim=-1))
```

`.mean(dim=1)` —— **把 16 个邻居的关系描述全部混成一杯**，再问「你周围平均来说是什么样」。
没有任何可学习的消息，纯粹看周围长什么样。

生物语言：你能知道的是「我周围密不密」「有几个邻居是从老远折回来的」
（后者几乎等于「我在不在茎区」）。你**不知道**的是：
对面那个配对的具体是什么姿态、离我多近——**而那恰恰是唯一能定碱基的信息。**

所以这一关的模型大概能学会「我在茎区」这种粗判断，
学不会「我对面那个是 G，所以我是 C」。后者要等第 4 关的消息传递
（`EncLayer`），它会把这个 `.mean()` 换成可学习的消息，
让模型能针对每一个邻居单独决定取什么、忽略什么。

**第 3 关是把食材准备好（建图、算接触指纹、验证几何没算错），第 4 关才是开火做菜。**
顺序是故意的：先确认输入造对了（8/8 几何测试），
否则将来网络不 work，分不清是特征错了还是结构错了。

# 三、实验记录

## 练习 1 · k 从 16 改成 4，再改成 32。k 越大越好吗

**答案：不是，会饱和。**

ProteinMPNN 原文做过一模一样的实验
（[Dauparas et al., Science 2022](https://www.bakerlab.org/wp-content/uploads/2022/09/Dauparas_etal_Science2022_Sequence_design_via_ProteinMPNN.pdf)）：

> tested "16, 24, 32, 48, and 64 nearest Cα neighbor neural networks" and
> "found that performance was saturated at 32-48 neighbors"

三层原因：超过一定半径的邻居本来就不带身份信息；边特征是 `[L, k, 289]`，
k 翻倍内存和算力也翻倍；而且 **k 和消息传递层数互相替代**——
层数多的时候信息能传几跳，小 k 也够。

### 本关实测（待补完）

|---|---|---|---|
| 4 | | | |
| 16 | | | |
| 32 | | | |

初次观察：10 轮看不出区别（太早）；40 轮下 32 比 16 多约 1.x 个百分点，
16 比 4 只多 0.01（单位待核对：0.01 个百分点，还是 0.01 = 1 个百分点？）。

**这组数还不能下结论，有两个问题：**

1. **只跑了一次。** 第 2 关已经吃过这个亏——单跑 64 得 50.3%，3 个种子均值只有 49.5%，
   那 0.8 是运气。这里必须同样跑 3 个种子，把抖动量先量出来。
2. **形状可疑。** 4 ≈ 16 但 32 突然高 1.x，非单调。

### 一个和原文对不上的地方，是本关特有的

**平均池化下，k 变大会稀释信号。** 把 16 个更远的、不带信息的邻居兑进平均，
对家那一份就被摊薄了。ProteinMPNN 说 32–48 饱和，那是**消息传递**的结论——
它能学会忽略无关邻居，`.mean()` 没这个本事。

所以本关的最优 k 理论上应该**偏小**，和原文对不上是正常的。

**预测（第 4 关回来验）：换成消息传递之后重跑这个实验，最优 k 会往大的方向移。**

## 练习 2 · 关掉相对位置 one-hot，掉多少

### 怎么关

不用永久改 `features.py`，临时替换掉就行：

```python
import minif.features as F
_orig = F.edge_features
R = 2 * F.MAX_OFF + 1          # 33

def no_relpos(coords, idx, resnum, mol="rna"):
    e = _orig(coords, idx, resnum, mol)
    e[..., -R:] = 0.0          # 最后 33 维整块置零
    return e

F.edge_features = no_relpos    # 之后 featurize / engine.prep 都走这个
# ...跑完务必还原...
F.edge_features = _orig
```

### 这里置零是合法的，和第 2 关不一样

第 2 关我特意强调「删列不要置零」，因为 cos=0 是一个**真实取值**（90°），
模型会当成真角度去学。

但 one-hot 块全 0 **不是一个合法的 one-hot**，含义毫无歧义就是「没有这个信息」。
而且维度保持 289 不变，模型一行不用改。

**判据：全 0 在这个编码里是不是一个合法取值。** 是 → 必须删列；不是 → 可以置零。

### 结果（待跑）

| 配置 | 恢复率（最好） | 最后一轮 | 比完整版 |
|---|---|---|---|
| 完整 289 维 | | | — |
| 关掉 relpos（后 33 维置零） | | | |

**预测：这一关掉幅会偏小。** 因为平均之后那 33 维变成
「我的 k 个邻居的序列偏移分布直方图」，还保留了「有几个邻居是从老远折回来的」
这种聚合信息（这几乎就是「我配不配对」），只是丢了「哪个邻居对应哪个偏移」。
到第 4 关消息传递能用上后者，掉幅应该更大。**第 4 关回来验。**

# 四、自测三问（含答案）

## 1. 结构输入为什么只用距离，不用坐标？

**因为距离在旋转和平移下不变，坐标不是。**

同一条 RNA 在空间里转一下、挪一下，还是同一条 RNA，模型的输出必须一样。
如果直接喂 xyz 坐标，模型得自己从数据里学会「转一下结果不变」这件事，
纯属浪费容量——还学不干净，训练集里没见过的朝向就会出错。
用距离就是把这个不变性**写死在输入里**，模型根本不需要学。
`tests/test_geometry.py` 第 5 条验的就是这个。

**但距离丢掉了手性。** 一个结构和它的镜像，所有原子间距完全相同。

所以要注意一个本仓库的细节：**RNA 的边特征（纯距离 + 相对位置）本身是镜像不变的。**
RNA 的手性信息**全部来自点特征里那三个扭转角**（二面角有符号，镜像后取反）。
蛋白那边多一个虚拟 Cβ，它是按手性公式摆的，所以蛋白的边特征也能分左右。

推论：**如果哪天把 RNA 的扭转角从点特征里删掉，模型就分不清右手 A 型螺旋
和它的左手镜像了。** `tests/test_geometry.py` 第 6 条测镜像，
但它只测 `F.node_features`——可以补一条专门测边特征的，记进第 7 关。

## 2. 相对序列位置这个特征在 RNA 上为什么格外重要？

**先更正题目：这个说法我拿不出证据，蛋白那边一样用。**

ProteinMPNN 也有相对位置编码，而且截断范围更宽（±32，本仓库是 ±16）。
所以「RNA 格外重要」目前只是个**假说**，不是事实。

**假说的内容**：RNA 的碱基身份主要由配对伙伴决定（G-C、A-U 几乎是确定性的），
而配对伙伴正是那个「序列上很远、空间上很近」的邻居——
相对位置是认出它的关键线索。蛋白那边接触更弥散（疏水核心堆积），
单个伙伴没这么强的决定性。

**练习 2 的跨分子对比就是这个假说的检验。** 掉幅 RNA 明显大于蛋白，假说成立；
差不多，就得承认这条说法站不住，老实改掉。

## 3. A 型螺旋在 eta-theta 图上聚成一团，这说明什么？

**说明 RNA 的局部构象自由度很小，绝大多数核苷酸的骨架姿势几乎一模一样。**

关键在推论——

**（a）限制**：如果所有残基局部看起来都一样，那**局部几何就区分不出碱基身份**。
第 2 关实测对上了：仅 eta/theta 只有 37.6%，比基准线 34.9% 才高 2.7 个百分点。
A 型螺旋的几何本来就是碱基无关的，茎区里 G 和 U 的骨架姿势没区别。

**（b）出路**：所以身份信息不在残基自己身上，**在残基之间的关系里**——
谁挨着谁、谁和谁配对、在什么 motif 里。**这就是第 3 关要加图的全部理由。**

**（c）工程用途**：这张图是个验证手段。原子解析错了、顺序搞反了，就不会聚成那一团。

# 五、和官方实现的差异（累积）

| 项 | 本仓库 | 原文 | 第几关发现 |
|---|---|---|---|
| 相对位置截断 | ±16 | ProteinMPNN ±32 | 3 |

# 六、没想通的 / 留给第 4 关验的预测

1. **k 的最优值**。预测：换成消息传递后往大的方向移（平均池化会稀释）。
2. **relpos 的掉幅**。预测：第 4 关比第 3 关大（平均池化只保留了聚合信息）。
3. **相对位置在 RNA 上是否真的格外重要**。等练习 2 的跨分子对比。
4. **网络能不能自己发现配对**。如果 16 个原子对距离 + 相对位置够用，
   第 2 关手喂的那一维配对标记就能删掉——顺带解决第 2 关查出来的泄漏问题。
   检验办法：第 4 关把那一维关掉，看掉多少。
